# perf-lab

把书上的性能论断**自己量一遍**。

这里不是库，是一组小实验——每个只回答一个具体问题，都带可复现的代码、实测数字，以及**当数字和预期对不上时的排查过程**。

## 写这些实验的几条自我要求

**① 每个实验必须能自证没测错。**
benchmark 最危险的不是跑不出来，是**跑出一个错的数字而你以为它对**。所以代码里带自检——比如 TLB 实验会验证指针环真的随机（步长非恒定）且覆盖全部槽位，不通过就直接退出，而不是给你一个漂亮但无意义的数字。

**② 数字要带适用边界。**
虚拟机还是物理机、几个物理核、有没有开透明大页、PMU 是否被屏蔽——这些不写清楚，数字就没法被别人复用，也没法和别人的对比。

**③ 不符合预期时，先怀疑测量，再怀疑预期——但两个都要怀疑。**
TLB 那个实验里，我排查了四个经典测量陷阱都没命中，最后是 `perf` 的计数器证明测量一直是对的，**错的是我脑子里「TLB miss = 4 次内存访问」那个模型**。

**④ 只写自己真的跑过的数字。**
没跑通的就标 TODO，不用别处的示例数据凑。

## 环境

实验在阿里云 `ecs.c9i.large`（Intel Xeon 6982P-C @3.9GHz，1 物理核 + 超线程，Ubuntu 24.04 / 内核 6.8）上跑。**这是虚拟机**，二维页表（EPT）会放大 TLB miss 的最坏代价，绝对值不能直接外推到物理机——各实验的 README 里会具体说明。

多数实验只需要 `gcc` 和 Linux；用到大页、VFIO、CUDA 的会在各自目录里注明。
